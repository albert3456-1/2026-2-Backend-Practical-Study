## DDD를 사용하는 프로젝트
핵심 복잡도가 비즈니스로직, 즉 프로젝트에서 가장 까다로운 부분이 세세한 조건 처리일때 적합하다.  
도메인 규칙이 복잡하고 자주 바뀌는 시스템에 적합하다.  
한편, 개인 프로젝트보단 협업에 유리하다.
## DDD 장단
# 장점
```
1. 외부에서 건들지 못하니 응집도가 상승한다.
2. 유지보수와 테스트에 용이하다.
3. 코드를 봐도 로직을 쉽게 알 수 있으니 가독성이 좋아진다.

```
# 단점
```
1. 계층 분리로 인한 클래스 수량의 증가
2. 쓸데없는 복잡도 증가 위험

```

## BigDecimal
파이썬 지식으로 미루어 보면....  
Decimal은 올림 내림 등 나눗셈과 소수점에 관련된 연산에서 늘 상 '정확한' 수치를 제공한다.
또한 Big은 크다라는 뜻을 가졌으니 아마 더 많은 바이트를 할당 받는 것이다.  
정리하자면, BigDecimal은 Long이랑 유사한 크기의 바이트를 할당 받으나, 더 세밀한 계산이 가능하므로  
1원이 소중한 금융업에선 중요하다고 추측할 수 있다.

...그리고 이 추측이 틀리지 않았다!

## 이펙티브 자바
```
1. 예외처리가 용이하다.
2. 명확한 이름을 가질 수 있다.
3. 생성된 객체를 재사용할 수 있다.
4. 반환 타입의 하위 객체를 반환할 수 있다.
5. 매개변수에 따라 다른 객체를 반환할 수 있다.
라는 장점을 가진다.
```
